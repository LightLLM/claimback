# Judging proof points

| Equally weighted criterion | Show, do not merely claim | Evidence in this build |
|---|---|---|
| Technical Implementation | A real Strands loop calls multiple guarded tools and stops for judgment | `claimback/agent.py`, exported tool-use transcript, policy tests; optional Bedrock mode and AgentCore entrypoint |
| Design | An understandable recovery desk with clear next actions | Responsive UI, evidence dialogs, shortfall card, explicit settlement acknowledgement, separate cash/replacement totals |
| Potential Impact | A specific audience and a completed administrative loop | Busy consumers following a cancelled booking and a broken household appliance through resolution; all demo outcomes labeled synthetic |
| Creativity & Originality | The agent detects a shortfall and knows when authority ends | $1,408 request versus $880 offer; $528 decision with evidence; model cannot accept settlement |
| Presentation | Two end-to-end stories within five minutes | 4:40 script, resettable fixtures, evidence export and architecture diagram |

## Claims discipline

Measured in the synthetic test scenario: three evidence sources per case; $528 refund-offer discrepancy; $1,408 simulated cash confirmation after challenge; $349 simulated non-cash replacement; one routine warranty follow-up. These are fixture outcomes, not user study results or forecasts.

User-value hypothesis: reducing repeated document assembly and status chasing helps consumers pursue claims they would otherwise abandon. Validate with consenting users by measuring completion rate, active user minutes per case, number of interruptions, error/overreach rate and actual recovered value. Do not invent market size, success rates or time savings.

The broader product can include reimbursements and other claims, but this submission demonstrates exactly two flows. An honest working slice is the basis of the pitch.
